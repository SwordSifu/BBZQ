# BBZQ 优化计划与验收方案

研究基线：`288a9be91f6dd213e0d378a9c071c7a1976b999f`（2026-09-05）。
本轮采用 gpt-5.6-luna / max 编码，由主代理逐项审核；调度接口没有独立 fast 参数。

## 已核实的现状

- 主分支 CI 运行 `33853123394` 成功；签名发布已改为手动选择，普通构建不依赖签名配置。
- CI 只监听 master push 和手动运行，没有 PR 验证。
- 下载接口在异常捕获范围外读取响应正文，正文读取异常可能丢失 UI 回调。
- 下载任务在 try/finally 之前创建目录，初始化失败可能使全局下载锁无法复位。
- 无音轨时使用缓存目录到公共下载目录的 renameTo，跨文件系统可能失败。
- 合并直接写最终文件，失败可能留下残缺文件或损坏已有同名下载。
- 音视频线程共同读写普通 Int 进度；下载到 100% 时 UI 已重新启用按钮，但合并尚未完成。
- MediaMuxerUtil 在 stop 之前返回 true，stop 异常被吞掉，而且 stop 抛错时 release 不执行。

## 本轮边界

保持现有签名发布策略，不要求新增密钥，也不改会员、地区或服务端权限相关逻辑。
本轮文件导出修复仍使用现有公共目录方案，不能替代后续分区存储适配。
本轮不更改全局视频身份捕获，因此快速切换视频导致的身份一致性风险仍需下一轮处理。
